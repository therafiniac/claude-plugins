## 2. Operable

- [ ] All functionality works with the keyboard alone, with no keyboard traps. (2.1.1, 2.1.2)
- [ ] Single-character keyboard shortcuts can be turned off, remapped, or only fire while their component has focus. (2.1.4)
- [ ] Focus order follows a logical sequence. Positive `tabindex` values are not used. (2.4.3)
- [ ] Every focusable element shows a clearly visible focus indicator. Focused elements are not hidden behind sticky headers, banners, or cookie bars. (2.4.7, 2.4.11)
- [ ] A skip link lets keyboard users bypass repeated navigation. (2.4.1)
- [ ] Every page has a unique, descriptive `<title>`. (2.4.2)
- [ ] Link and button text makes sense out of context. No repeated "click here" or "read more" without an accessible name that says more. (2.4.4)
- [ ] There is more than one way to find a page (navigation, search, sitemap, or links). (2.4.5)
- [ ] Headings and labels describe their topic or purpose. (2.4.6)
- [ ] Interactive targets are at least 24×24 CSS px, and 44×44 px is the design target for touch. (2.5.8)
- [ ] Any drag interaction has a single-pointer alternative, such as buttons or a menu. (2.5.7)
- [ ] Multi-point or path-based gestures have a single-pointer alternative. Pointer actions can be cancelled before completion. (2.5.1, 2.5.2)
- [ ] The visible label of a control is contained in its accessible name. (2.5.3)
- [ ] Time limits can be extended or turned off. Auto-updating, moving, or blinking content can be paused, stopped, or hidden. (2.2.1, 2.2.2)
- [ ] Nothing flashes more than three times per second. (2.3.1)
